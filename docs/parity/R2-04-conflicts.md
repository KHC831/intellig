## Top findings (ranked, this component)
1. **Standalone "Merge from…" front-door unwired (dialog exists, no command registration)** — Dialog is parity-complete (branch picker + 6 options + message textarea, mutex enforced), but NO `intellig.merge` command in package.json → no VCS menu entry, no palette action. User CANNOT invoke standalone merge without a branch context. IntelliJ: VCS → Git → Merge Changes... always available. **Severity: 🟠 HIGH (P2 blocker).** **Source:** git4idea (GitMerge.java:34-38 → GitMergeDialog.kt). **Effort: S** (1 command + menu + `when` clause). **Files to touch:** extension.ts (registerCommand), package.json (commands[] + menus.vcs), commands/registration/changelist.ts or new mergeCommands.ts. **Action:** register `intellig.merge` → opens MergeDialog with repo picker + branch autocomplete (reuse branchField pattern from dialog internals).

2. **sanitizeGitError incomplete (misses SCP-style ssh URLs, credential-helper tokens)** — sanitizeGitError (gitError.ts:21-33) only scrubs HTTPS basic-auth + SSH passphrase prompts. **GAPS:** (1) SCP-style `user@host:path` (common in clone errors) not scrubbed; (2) credential-helper tokens in error messages (rare but possible); (3) pathnames with sensitive data (e.g. `/Users/alice/.ssh/id_rsa` in permission errors). IntelliJ doesn't scrub either (logs to IDE-internal console, not user toasts), but intellig surfaces git stderr in showErrorMessage → higher exposure. **Severity: 🟡 MEDIUM (LOW per project scale, but real if user shares screenshot with embedded credentials).** **Source:** mixed (credential leakage is universal git concern). **Effort: S** (widen regex, add unit tests). **Files to touch:** git-core/gitError.ts:21-33, add test cases in gitError.test.ts. **Recommended regex additions:** (a) SCP ssh: `/([a-zA-Z0-9_.-]+)@([^:]+):/g` → `***@$2:`; (b) token patterns (`token`, `password`, `passphrase` keys in error JSON — rare but seen in credential-helper failures).

3. **3-way merge editor lacks syntax highlight + line-level diff + conflict-type classification** — MergeView.ts:1-607 is a custom webview (not VS Code's native merge editor). Displays 3 raw text blocks (original/current/incoming) with Accept/manual-edit. **GAPS:** (1) no syntax highlighting (Monaco editor not embedded); (2) no line-level diff indicators (added/removed/unchanged); (3) conflict-type classification absent (always MODIFIED_MODIFIED, no DU/UD/AA distinction in UI). VS Code's `vscode.open` with `?mergeEditor` param DOES have syntax+diff, but we don't delegate to it. IntelliJ: Platform diff-impl provides all 3 (syntax, line diff, type labels). **Severity: 🟡 MEDIUM (works for basic resolution, but polish gap).** **Source:** platform diff-impl. **Effort: L** (P4 platform-rebuild or delegate to VS Code's editor). **Files to touch:** MergeView.ts (full rewrite or switch to vscode.open delegation). **Decision fork:** (a) embed Monaco + diff algorithm (heavy lift, P4); (b) delegate to VS Code's merge editor (S effort, loses custom UI control); (c) defer to P4.

4. **Conflict-type classification not propagated to UI** — ConflictResolutionService.getConflictedFiles:367-379 filters `U-either` without extracting index/workTree chars (DU/UD/DD/AA/UU). IConflictedFile:{path,resolved} has no type field. ResolveConflictsDialog shows all conflicts identically (⚠ icon + Accept Yours/Theirs buttons). User can't see "ours deleted, theirs modified" vs "both added" at a glance. IntelliJ: GitConflict.Status enum (MODIFIED/DELETED/ADDED) + merge dialog shows "Deleted by You" / "Deleted by Them" / etc. **Severity: ⚪ POLISH (P3).** **Source:** git4idea. **Effort: S** (extend IConflictedFile with `type?: string`, extract from porcelain, render distinct labels/icons in dialog). **Files to touch:** interfaces/IConflictResolutionService.ts:29-32 (add type), ConflictResolutionService.ts:367-379 (extract), ResolveConflictsDialog.ts:469-492 (render type label).

## Security review (this component)
1. **Argv injection (path handling in accept ops):** ✅ SECURE. All paths passed after `--` separator in ConflictResolutionService acceptCurrent/acceptIncoming/acceptAllCurrent/acceptAllIncoming (lines 461, 523, 566, 614). Paths sourced from `getStatus` porcelain parser (never user input). Leading-dash filenames safe.

2. **Credential leakage in conflict errors:** 🟡 PARTIAL (see Top finding #2). sanitizeGitError scrubs HTTPS basic-auth + SSH passphrase prompts, but misses SCP-style `user@host:`, credential-helper tokens, sensitive pathnames. ResolveConflictsDialog + MergeDialog both call sanitizeGitError before showErrorMessage, so the mitigation is present but incomplete. **Action:** widen sanitizeGitError (P3 hardening).

3. **CSP (webview Content-Security-Policy):** ✅ SECURE. MergeDialog._buildCsp:unreviewed-in-depth (inherited from BaseWebviewPanel), but MergeDialog._render:341-366 + ResolveConflictsDialog._render:383-463 both emit CSP meta tag with nonce-gated script. No inline event handlers, no `eval`. ResolveConflictsDialog uses data-action delegation (click:411-429) instead of inline onclick.

4. **Destructive-op confirms:** ✅ CORRECT per feedback_data_loss_confirms.md (IntelliJ-minimal policy). MergeDialog has NO confirm (merge is recoverable via `git merge --abort`). ResolveConflictsDialog._handleSkip:697-734 has ONE modal confirm ("Skip this commit? The changes will NOT be applied.") — matches IntelliJ GitRebaseDialog skip confirm. acceptCurrent/acceptIncoming have NO confirm (file-level accept is recoverable via manual edit or Accept opposite side). **No over-prompting, no under-prompting.**

5. **Unsanitized surfaces (toasts, log):** ✅ MITIGATED. All user-facing error toasts go through sanitizeGitError (ResolveConflictsDialog:540,553,566; MergeDialog:453). Logger (getLogger().error) is internal-only (not user-facing). ResolveConflictsDialog.escapeHtml:188-195 escapes branch names + file paths before injecting into webview (no XSS). MergeDialog.escapeHtml:469-476 likewise. **No raw git stderr → DOM injection path found.**
