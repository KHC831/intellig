## Top findings (ranked, this component) — _re-audited 2026-06-21_
**Three of the four prior findings are RESOLVED/stale** (front-door wired, native merge editor, broadened sanitizer — see the gap table). Remaining:

1. **Revert-resolved affordance missing (`Git.RevertResolved`)** — no in-product way to send a resolved/staged file back to its conflicted state to redo a mis-resolution; user must `git checkout -m -- <file>` from a terminal. IntelliJ exposes it in the main + context menus during/after a merge. **Severity: 🟡 MEDIUM (recovery affordance).** **Source:** git4idea (`GitRevertResolvedAction`). **Effort: S** (add `ConflictResolutionService.revertResolved` → `git checkout --merge -- <file>` + command + Conflicts-list entry).

2. **Conflict-type classification not propagated to UI** — ConflictResolutionService.getConflictedFiles:367-379 filters `U-either` without surfacing the index/workTree chars (DU/UD/DD/AA/UU) to the list. IConflictedFile:{path,resolved} has no type field. ResolveConflictsDialog shows all conflicts identically. (Note: the *resolution* layer already distinguishes DU/UD/DD for correct `git rm` routing — only the user-facing *label* is missing.) IntelliJ shows "Deleted by You" / "Deleted by Them" / etc. **Severity: ⚪ POLISH (P3).** **Effort: S** (extend IConflictedFile with `type?`, render distinct labels in dialog).

## Security review (this component)
1. **Argv injection (path handling in accept ops):** ✅ SECURE. All paths passed after `--` separator in ConflictResolutionService acceptCurrent/acceptIncoming/acceptAllCurrent/acceptAllIncoming (lines 461, 523, 566, 614). Paths sourced from `getStatus` porcelain parser (never user input). Leading-dash filenames safe.

2. **Credential leakage in conflict errors:** ✅ MITIGATED. sanitizeGitError redacts any-scheme `user:pass@host`, the standard PAT form (`https://TOKEN@host`, secret-shaped-userinfo gated), SSH passphrase prompts, and home-dir paths. ResolveConflictsDialog + MergeDialog both call it before showErrorMessage. SCP-form `git@host:path` carries no secret (passes through correctly).

3. **CSP (webview Content-Security-Policy):** ✅ SECURE. MergeDialog._buildCsp:unreviewed-in-depth (inherited from BaseWebviewPanel), but MergeDialog._render:341-366 + ResolveConflictsDialog._render:383-463 both emit CSP meta tag with nonce-gated script. No inline event handlers, no `eval`. ResolveConflictsDialog uses data-action delegation (click:411-429) instead of inline onclick.

4. **Destructive-op confirms:** ✅ CORRECT per feedback_data_loss_confirms.md (IntelliJ-minimal policy). MergeDialog has NO confirm (merge is recoverable via `git merge --abort`). ResolveConflictsDialog._handleSkip:697-734 has ONE modal confirm ("Skip this commit? The changes will NOT be applied.") — matches IntelliJ GitRebaseDialog skip confirm. acceptCurrent/acceptIncoming have NO confirm (file-level accept is recoverable via manual edit or Accept opposite side). **No over-prompting, no under-prompting.**

5. **Unsanitized surfaces (toasts, log):** ✅ MITIGATED. All user-facing error toasts go through sanitizeGitError (ResolveConflictsDialog:540,553,566; MergeDialog:453). Logger (getLogger().error) is internal-only (not user-facing). ResolveConflictsDialog.escapeHtml:188-195 escapes branch names + file paths before injecting into webview (no XSS). MergeDialog.escapeHtml:469-476 likewise. **No raw git stderr → DOM injection path found.**
